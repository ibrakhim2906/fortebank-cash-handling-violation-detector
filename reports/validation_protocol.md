# MISSION validation protocol, version 1

The 42 supplied files contain 40 distinct full-byte SHA-256 groups (21 positive,19 negative). Original labels are weak video/anchor annotations; the separately confirmed human review supplies 22 timestamp-events and 28 type assignments. Multiple types at the same timestamp form one matching target. The duplicate positive keeps both57s and68s. The Х-13 disagreement remains flagged. No label is passed to inference.

All supplied recordings were inspected earlier at the human's explicit request. The new10-group reserve is **previously seen prospective regression data, not an independent test**. Its list is reports/holdout.txt; immutable split/fold membership and protocol fingerprint are in data/processed/mission-validation-v1.json. No reserve error inspection is permitted during the new loop; aggregate checkpoints are capped at four. New authorized recordings, if supplied, remain test-only.

The team supplied only three camera setups. The overlap for Х-33 resolves to the explicitly described blue-chair room(c). Leave-one-setup-out uses these actual groups, with validation sizes26,1,3 on the30 development groups. The other4 videos available when excluding the dominant setup cannot support reliable per-type calibration. This imbalance and the small minor setups make uncertainty substantial. Five artificial folds would not repair it.

Metrics include every requested video. A failure never counts as correct clean. Positive failures count as misses. Event matching maximizes cardinality, then minimizes time error, one-to-one, separately at±1s and±2s. Type accuracy uses the±2s matches and accepts any annotated type at that event; extra predictions remain explicit false events. Timing/type/source applicability and evidence validity are separate concerns. Missing type truth is not invented. The original frozen src/eval.py and historical src/video_eval.py remain unchanged.

Cross-fitting fits optional offsets only on a fold's training groups (at least three consistent examples). A fixed pretrained policy needs no supervised fit; sharing that fixed policy across excluded setups is reported explicitly. Historical prompt/rule selection exposure remains: this is not an unbiased generalization estimate even after cross-fitting. Any later fitted fusion/threshold must similarly exclude validation labels.

Robustness variants are horizontal flip,12% crop,±10° rotation,35% darker,0.75 resolution,and re-encoding. Copies retain their source group. Generation time is excluded from inference latency; actual API timing includes upload,queue,and polling. A renamed/re-encoded serving replay compares verdict,types and source-time tolerance; evidence bytes may differ legitimately after re-encoding. Stress transforms do not establish robustness to a new physical camera angle.

The rubric is an engineering proxy. Stub/resubstitution reports cannot earn honest-validation points. Product points need a complete real API report,pytest pass and measured≤200s worst latency. Tech points need a real network-denied inference pass and verified license table. Unknown/missing gates receive zero points. No proxy number is promised as the jury grade.

Freeze after regression tests: scripts/eval_video.py is mission-owned; its SHA is recorded in each report and in docs/decisions.md. The human's explicit end-to-end MISSION instruction delegates the prerequisite review rather than requesting another approval interruption. No human code review is claimed. Future evaluator metric changes require explicit authorization; orchestration and output adapters remain separate.
