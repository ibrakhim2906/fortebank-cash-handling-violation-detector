# CashLint: выявление нарушений кассовых операций (ForteBank)

[English version](README.md)

Локальный сервис анализа видеозаписей кассы. Загрузите запись и получите:
- вердикт (есть нарушение или нет);
- для каждого события: тип, таймкод и кадры-доказательства;
- описание с конкретным пунктом НБРК №231, к которому относится событие.

Весь анализ выполняется на нашем GPU открытой моделью. Облачные ИИ-сервисы не используются, лица не распознаются, сервис работает при заблокированной сети.

**Веб-интерфейс и API:** `https://p7ayn21cpy6voe-8000.proxy.runpod.net` (ключ API передан жюри отдельно).

## Как это работает

```
загрузка .mov → выборка кадров (16 обзорных изображений с исходными таймкодами)
              → обзор моделью Qwen3-VL-32B-Instruct-AWQ: кандидаты событий по 14 типам
              → плотная перепроверка каждого кандидата (неподтверждённое отбрасывается)
              → контрпримеры хранения для «деньги/сейф без присмотра» (меньше ложных срабатываний)
              → повторный проход со сдвигом кадров: поиск пропущенных и сомнительных событий
              → JSON: вердикт, типы, таймкоды, кадры-доказательства, цитата нормы
```

- **Модель:** `QuantTrio/Qwen3-VL-32B-Instruct-AWQ` (Apache-2.0), vLLM 0.11.0 на одной A40, порт `127.0.0.1:8002` наружу не открыт.
- **Сервис:** FastAPI (`service/app.py`), асинхронные задачи: запрос сразу возвращает идентификатор. Одна задача за раз, бюджет анализа 185 с в пределах 5-минутного лимита.
- **Конвейер:** `service/pipeline/analyze.py` управляет шагами; `service/pipeline/auditor.py` содержит этапы модели.
- **Правила:** `service/rules.json`: 14 типов нарушений с названиями на русском и английском и, где проверено, точной цитатой нормативного акта.

## Измеренные результаты

Все цифры получены на реальных прогонах неизменным оценщиком (`scripts/eval_video.py`). Команда просматривала все 40 видео при разработке, поэтому это не независимая тестовая оценка.

| Конфигурация | Данные | Верные вердикты | TP / FN / FP | Таймкод ±2 с |
|---|---|---:|---|---:|
| Основная (контрпримеры хранения) | DEV30 | 23/30 | 12 / 4 / 3 | 5/16 |
| **+ повторный проход** | DEV30 | **24/30** | 13 / 3 / 3 | 5/16 |
| Основная, публичный API | все 40 | 27/40 | 13 / 8 / 5 | 6/22 |
| **+ повторный проход** | все 40 | **28/40** | 14 / 7 / 5 | 6/22 |
| + повторный проход, **зеркальное видео** (устойчивость) | DEV30 | 19/30 | 11 / 5 / 5, 1 сбой | 7/16 |
| + повторный проход, **поворот 10°** (устойчивость) | DEV30 | 20/30 | 8 / 8 / 2, 1 сбой | 4/16 |

- **Время:** самая долгая из 40 загрузок через публичный API заняла 73,0 с, два повтора 64,9 и 65,9 с; всё в пределах 5 минут.
- **Типы событий:** каждое событие, найденное в нужное время, классифицировано верно.
- **Журнал:** все эксперименты, включая отклонённые, записаны в `experiments.md`.

## Правовое обоснование

Семь типов нарушений цитируют точный текст действующей редакции **НБРК №231 «Правила ведения кассовых операций»**, полученный через API Adilet; SHA-256 текста сохранён в `service/rules.json`.

| Тип | Пункт |
|---|---|
| Наличные вне хранилища, сейф открыт | п.20, ч.2: принятые наличные хранятся в устройствах, закрывающихся на ключ |
| Пересчёт без клиента | п.20, ч.1: наличные принимаются и пересчитываются в присутствии клиента |
| Нет полистного пересчёта | п.19, пп.2 |
| Нет проверки личности | п.19, пп.1 |
| Клиенту не выдан документ | п.19, пп.6 |
| Личные вещи в кассовом узле | п.12 |

Для типов без прямо применимой нормы (дверь, ключи, еда, чтение) правовых утверждений нет. В каждом описании указано, что применимость проверяет человек. Источники и их ограничения: `docs/action_rule_candidates.md`.

## Ограничения

- **Таймкоды:** длящиеся состояния (деньги на столе, открытая дверь) часто отмечаются при первом появлении, раньше момента в разметке, поэтому большинство выходит за ±2 с.
- **Пропущенные действия** (нет документа, нет проверки личности, пересчёт без клиента) редко обнаруживаются по выборке кадров: отсутствие действия намеренно не выводится из кадров, которых модель не видела.
- **Проверка:** все 40 видео просматривались при разработке; на новой камере система проверена только искусственными искажениями (зеркало, поворот).
